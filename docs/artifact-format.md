# Artifact format

Every completed timed run has three independent evidence layers: a primal
solution, a normalized metadata record, and solver/progress logs.  Certificate
directories add a proof record and a sparse optimal witness.

## Solution

`artifacts/solutions/<problem>/dense/<instance>.npz` stores complete arrays:

- SSCFLP: binary `x[n,m]` and `y[m]`;
- MS-CFLP: continuous `x[n,m]` and binary `y[m]`;
- MS-CFLP-CI: continuous `x[n,m]`, binary `y[m]`, and binary `a[n,m]`.

Archived MS-CFLP and CI solvers wrote only the full flow matrix.  Their public
canonical representation preserves every flow value and sets `y_j=1` exactly
when facility `j` carries positive flow; for CI it also sets `a_ij=1` exactly
when `x_ij` is positive.  This produces the same feasible objective and is
recorded as `solution_source` in metadata.

The matching `sparse/<instance>.csv.gz` contains columns `variable`,
`index_1`, `index_2`, and `value`.  Indices are one-based.  Entries omitted at
the documented tolerance are zero.  Both timed-run encodings are independently
hashed.  Certificate witnesses use only the sparse encoding.

## Metadata

`artifacts/metadata/<problem>/<instance>.json` records dimensions, protocol,
calculated PAR parameters, graph size, solver status, objective and bound,
timings, validation, provenance, and artifact hashes.  The
`released_solution.objective` field is the canonical value independently
recomputed from the published primal arrays.  The historical value emitted by
the archived solver remains in `solver.objective` and is repeated in the
reconciliation block.  Metadata contains no absolute local path or license
information.

## Logs and progress

Gurobi logs and constructive-initializer logs are under `artifacts/logs/`.
End-to-end checkpoint traces are under `artifacts/progress/`.  They are gzip
compressed.  Local filesystem paths, registration e-mail addresses, and
license identifiers are replaced by explicit redaction markers in released
logs; numerical solver output is unchanged.  Metadata stores both the
repository-relative path and SHA-256 of every log and progress trace.

## Certificates

The release has 368 full-model optimality certificates in three families.
Every certificate directory is self-contained:

```text
certificates/
├── sscflp/records/<instance>/          # 150
│   ├── certificate.json
│   ├── optimal_solution.csv.gz
│   ├── verification.log.gz             # 149; p800-4400-88 has none
│   └── pricing_iterations.csv          # 131 phasewise
├── mscflp/records/<instance>/          # 209
│   ├── certificate.json
│   ├── optimal_solution.csv.gz
│   └── verification.log.gz
└── mscflp-ci/records/<instance>/       # 9
    ├── certificate.json
    └── optimal_solution.csv.gz         # 5; four have no witness
```

`certificate.json` stores the instance-specific objective, bound, proof
tolerance, classification, proof basis, timings, source hashes, and the
repository-relative path and SHA-256 of the witness and proof logs.  SSCFLP
records use `trace_profile` to distinguish `lp_pricing_phasewise` from
`terminal_safe_support`; MS-CFLP records use `proof_basis =
global_MIP_bound`; CI records use `optimal_solution_available` to identify the
four records without a preserved witness.

The canonical indices are:

- `results/certificates/sscflp_all_certificates.csv` — 150 rows;
- `results/certificates/mscflp_certificates.csv` — 209 rows;
- `results/certificates/mscflp_ci_certificates.csv` — 9 rows.

`results/summaries/certificate_validation.csv` has 155 rows (131 phasewise
SSCFLP, 19 terminal SSCFLP, and 5 CI).  The certificate `README.md` records the
common provenance, the 209/83/117/9 MS-CFLP split, the treatment of
`p800-4400-88` (no verification log because fixing closed the proof), and the
redaction policy.

New proof runs write `certificate.json`, a sparse optimal witness, and the
solver log under the requested output directory.  `src/certify.py` handles
SSCFLP; `src/certify_mscflp.py` solves the complete MS-CFLP model;
`src/certify_ci.py` solves the complete CI model with lazy conflict
separation.  Reproducible but very large temporary omitted-arc dumps and
simplex basis files are excluded; they can be regenerated by the certifiers.
